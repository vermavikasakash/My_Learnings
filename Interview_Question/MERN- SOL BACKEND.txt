A Forward Proxy represents the client. The website thinks: "The request came from the proxy."
Client -> Forward Proxy -> Internet -> Web
usecases : Hide client IP, Access blocked websites,Content filtering, Corporate networks

A Reverse Proxy represents the server. eg nginx

 Client ->Reverse Proxy -> Many backend servers

usecases: Load balancing, Security, Caching,Routing

The client thinks: "I'm talking to one server.",But the reverse proxy forwards the request to one of many backend servers.

QUES 1 : Event loop in node.js 
✅ ANS:  
Node.js is a free, open-source, cross-platform JavaScript runtime environment let us run JavaScript code on a server.
Key Features: It is fast, scalable, and uses an event-driven, non-blocking architecture, making it excellent for real-time apps like chat apps, streaming services, or online games.
Why it matters: It lets programmers use a single language (JavaScript) to write both the front-end  and the back-end of a web application.

The event loop is a mechanism which allows Node.js to handle asynchronous operations by executing their callbacks when the call stack is free.

"Node.js runs JavaScript on a single main thread using the V8 engine. When synchronous code executes, it runs directly on the call stack and blocks call stack until completion. For asynchronous operations, Node.js delegates the work to libuv. Some operations, such as file system access and cryptographic functions, are handled by thread pool, while network I/O relies on the operating system's non-blocking APIs. Once an asynchronous operation completes, its callback is placed into the appropriate event loop queue. The event loop continuously checks whether the call stack is empty. When it is, the event loop moves the next ready callback from the queue to the call stack for execution."

"All asynchronous operations are coordinated by libuv, but not all of them use the thread pool. File system operations, compression, cryptographic functions, and DNS lookups (in many cases) typically use the libuv thread pool. Network I/O and timers do not; they rely on the operating system's non-blocking event notification mechanisms, and libuv simply listens for those events."

QUES 2.What is cluster in node js?
✅ ANS: In Node.js, a cluster is a group of worker processes that share the same server port.
 Clustering allows you to take advantage of multi-core processors and scale your application.

How Clustering Works
1. A master process is created, which listens for incoming connections.
2. The master process forks multiple worker processes, which share the same server port.
3. Incoming connections are distributed among the worker processes.
4. Each worker process handles the incoming connections independently.

Benefits of Clustering
1. *Improved Performance*: By utilizing multiple cores, clustering can significantly improve the performance of your application.
2. *Scalability*: Clustering allows you to scale your application horizontally by adding more worker processes.
3. *Fault Tolerance*: If one worker process crashes, the other worker processes can continue to handle incoming connections.

Node.js Cluster Module
Node.js provides a built-in `cluster` module that makes it easy to create and manage clusters. Here's an example:

```
const cluster = require('cluster');
const http = require('http');
const numCPUs = require('os').cpus().length;

if (cluster.isMaster) {
  console.log(`Master ${process.pid} is running`);

  // Fork workers.
  for (let i = 0; i < numCPUs; i++) {
    cluster.fork();
  }

  cluster.on('exit', (worker, code, signal) => {
    console.log(`worker ${worker.process.pid} died`);
  });
} else {
  // Workers can share any TCP connection
  // In this case it is an HTTP server
  http.createServer((req, res) => {
    res.writeHead(200);
    res.end('hello world\n');
  }).listen(8000);

  console.log(`Worker ${process.pid} started`);
}
```

QUES 3:What is setImmediate & process.nextTick() in node (micro or macro tasks),
✅ ANS: setImmediate() schedules a callback to run in the Check phase of the next iteration of the Node.js event loop. This phase comes after the Poll phase, where I/O callbacks are executed.

"process.nextTick() callbacks are executed after the current (synchronous) operation completes but before the event loop proceeds to the next phase. 
setImmediate() callbacks are executed during the check phase, which comes after the poll phase where I/O callbacks are processed."


QUES 4 :What is piping in node js
ANS ✅: piping is a mechanism that allows you to connect multiple streams together, enabling the output of one stream to be used as the input for another stream.

What are streams?
In Node.js, Buffer and Stream are core concepts used for handling binary data and large data efficiently.

A Buffer is a temporary memory area used to store raw binary data in chunks.
A Stream processes data chunk-by-chunk instead of loading everything into memory at once.

Buffer = temporary memory chunk
Stream = continuous flow of chunks

“A Buffer in Node.js is a temporary binary memory container used to store raw data,
 while a Stream processes data incrementally in chunks instead of loading everything into memory at once. 

Streams are more memory efficient and are commonly used for large file processing, uploads, and real-time data handling.”

"A Buffer in Node.js is a fixed-size block of memory used to store raw binary data outside the V8 heap. It's useful for handling files, network packets, and streams. During streaming, data is transferred in small chunks, and each chunk is represented as a Buffer, allowing Node.js to process large files efficiently without loading everything into memory."

"Buffers are allocated outside the V8 heap because they often store large binary data such as files, images, videos, and network packets. Keeping this data outside the V8 heap prevents excessive garbage collection and allows V8 to focus on managing JavaScript objects efficiently, improving both memory usage and performance."

- *Readable streams*: Allow you to read data from a source.
- *Writable streams*: Allow you to write data to a destination.
- *Duplex streams*: Allow you to both read and write data.
- *Transform streams*: Allow you to modify data as it flows through the stream.

How piping works
Piping involves connecting the output of one stream to the input of another stream. This creates a pipeline of streams that can process data in a series of steps.

Here's an example of piping:

```
const fs = require("fs");

const readStream = fs.createReadStream("input.txt");    // reads the file in chunks.
const writeStream = fs.createWriteStream("output.txt"); // Create a writable stream to write

readStream.pipe(writeStream); // Pipe the streams together

console.log("File copy started...");
```

The `pipe()` method is used to connect the streams together, creating a pipeline that processes the data in a series of steps.

Benefits of piping
Piping provides several benefits:

- *Efficient data processing*: Piping allows you to process data in a series of steps, making it more efficient than processing data in a single step.
- *Memory efficiency*: Piping allows you to process large amounts of data without loading it all into memory at once.
- *Modularity*: Piping enables you to break down complex data processing tasks into smaller, more manageable modules.


QUES 5 :Difference between authentication and authorization
✅ ANS: In the context of MERN (MongoDB, Express, React, Node.js) stack, authentication and authorization are two related but distinct concepts:
Authentication verifies the user's identity, while authorization determines what actions the authenticated/verifed user can perform on protected resources.

Authentication
Authentication is the process of verifying the identity of a user or client. It involves checking the credentials provided by the user, such as username and password, to ensure that they are genuine and valid.

 Authentication typically involves: User registration, User login, Verification,

Authorization
Authorization is the process of determining what actions an authenticated user can perform on a protected resource. It involves checking the user's permissions, roles, or access control lists (ACLs) to ensure that they have the necessary privileges to access or modify the resource.

Authorization typically involves: Role-based access control (RBAC), Attribute-based access control (ABAC) i.e policy based, Access control lists (ACLs) i.e users or groups

QUES 12 :What is callback in node
✅ ANS: a callback is a function that is passed as an argument to another function, which is then executed by that function when a specific operation is complete.

Characteristics of callbacks
Here are some key characteristics of callbacks in Node.js:

1. *Asynchronous*: Callbacks are used to handle asynchronous operations, such as I/O operations, network requests, or database queries.
2. *Function as an argument*: A callback is a function that is passed as an argument to another function.
3. *Executed by the caller*: The callback function is executed by the function that received it as an argument, typically when a specific operation is complete.



Types of callbacks
There are two types of callbacks in Node.js:

1. *Error-first callbacks*: These callbacks take an error as their first argument, followed by the result of the operation. This pattern is commonly used in Node.js APIs.
2. *Regular callbacks*: These callbacks do not take an error as their first argument. Instead, they may take a result or other arguments.

Advantages:

- *Asynchronous*: Callbacks enable asynchronous programming, which is essential for I/O-bound operations.
- *Non-blocking*: Callbacks allow Node.js to continue executing other tasks while waiting for an operation to complete.

Disadvantages:

- *Callback hell*: Deeply nested callbacks can lead to code that is difficult to read and maintain.
- *Error handling*: Callbacks require manual error handling, which can be cumbersome.

In Node.js, error handling evolved in stages:

1.Error-first callbacks
2.Promises (.then/.catch)
3.try-catch
4.async-await

1.Error-first callbacks

const fs = require("fs");

fs.readFile("test.txt", "utf-8", (error, data) => {

    if (error) {
        console.log("Error:", error.message);
        return;
    }

    console.log(data);
});

2.Promises (.then/.catch)

const fs = require("fs/promises");

fs.readFile("test.txt", "utf-8")
   .then((data) => {
       console.log(data);
   })
   .catch((error) => {
       console.log("Error:", error.message);
   });

3. or 4. Async-Await + try-catch (Modern Approach)

const fs = require("fs/promises");

async function readData() {

    try {

        const data = await fs.readFile(
            "test.txt",
            "utf-8"
        );

        console.log(data);

    } catch (error) {

        console.log("Error:", error.message);
    }
}

readData();


Alternatives to callbacks
Node.js provides several alternatives to callbacks, including:

- *Promises*: A promise represents a value that may not be available yet. Promises provide a more structured approach to asynchronous programming.
- *Async/await*: Async/await is a syntax sugar on top of promises that makes asynchronous code look and feel synchronous.
