Monolithic architecture: The application is built as a single deployable unit, where different functionalities such as authentication, orders, payments, etc. are part of the same application/service.

Microservices architecture: The application is divided into multiple independently deployable services, where each service owns a specific business capability, such as auth service, order service, payment service, etc.

Q1. Why doesn't Cart Service directly use Socket.IO?

"The Cart Service is responsible only for cart business logic. It shouldn't know which frontend clients are connected or manage WebSocket connections. The Gateway already acts as the single entry point for the application, so it is the appropriate place to maintain Socket.IO connections. The Cart Service simply publishes a cart.updated event, and the Gateway consumes it and notifies connected clients."

Cart Service -> RabbitMQ -> Gateway -> Socket.IO -> Frontend

Q.10 How did you integrate Razorpay/payment service?

"The Payment Service creates a Razorpay order, the frontend opens Razorpay Checkout, and after payment Razorpay returns the payment ID, order ID, and signature. The frontend sends those values to my backend, where the Payment Service independently generates the expected HMAC-SHA256 signature using the Razorpay secret and compares it with the received signature. Only after successful verification do I create the final ecommerce order."

Verification :
"I generate the expected signature according to Razorpay's documented HMAC-SHA256 verification algorithm, using the Razorpay secret_key and the order ID and payment ID. I then compare that generated signature with the signature returned by Razorpay through the frontend. If they match, the payment response has been authenticated; if they don't, I reject it."

How do you know your generated signature is correct?
"I follow Razorpay's defined HMAC-SHA256 algorithm using the order ID, payment ID, and server-side secret. Razorpay generated the original signature using the same verification scheme, so matching signatures authenticate the response."

For a production system, I would add Razorpay webhooks as an additional server-to-server mechanism so that payment state can still be reconciled if the browser disconnects."

Where does the SSH key come from?
"When creating an EC2 instance, AWS lets us create or select a key pair. AWS stores the public key on the EC2 instance and downloads the private key (.pem) to our local machine. To allow GitHub Actions to connect securely, we store the private key as a GitHub Secret. During the workflow, the SSH action uses that private key to authenticate with the EC2 server."

"uses references a reusable GitHub Action. An Action is a packaged piece of automation that someone has already implemented. For example, actions/checkout checks out the repository, actions/setup-node installs Node.js, and appleboy/ssh-action establishes an SSH connection to a remote server so I can execute deployment commands."

--------------------AWS---------------------
EC2

Q1. What is EC2? How would you deploy a Node.js application on EC2?

Answer:
EC2 is a virtual server provided by AWS. I can launch an EC2 instance, connect to it using SSH, install Node.js and required dependencies, clone my application, configure environment variables, and run the application using something like PM2. I would also configure the required security-group ports.

Q2. What is a Security Group in EC2?

Answer:
A Security Group acts like a firewall for an EC2 instance. It controls which inbound and outbound traffic is allowed. For example, I can allow SSH on port 22 and HTTP/HTTPS traffic on ports 80/443.

S3

Q3. Why would you use S3 in a MERN application?

Answer:
I would use S3 to store files such as images, videos, PDFs, and user uploads instead of storing them on the EC2 server. S3 is designed for object storage and is more suitable for storing large files.

Q4. What is a pre-signed URL in S3?

Answer:
A pre-signed URL is a temporary URL generated by the backend that gives permission to access or upload a specific S3 object for a limited time. It allows the frontend to interact with S3 without exposing AWS credentials.

IAM

Q5. What is IAM and why is it important?

Answer:
IAM stands for Identity and Access Management. It controls who or what can access AWS resources and what actions they can perform. For example, I can give an EC2 application permission to upload files to a particular S3 bucket.

Q6. Why shouldn't you put AWS access keys directly in your Node.js code?

Answer:
Because anyone who gets access to the code could potentially use those credentials. I would use environment variables for local development and preferably an IAM role attached to EC2 for applications running on AWS.

Elastic Beanstalk

Q7. What is AWS Elastic Beanstalk?

Answer:
Elastic Beanstalk is a managed service that makes deploying applications easier. Instead of manually configuring EC2, I provide my application and Beanstalk manages things like the underlying EC2 instances, deployment, scaling, and health monitoring.

Q8. If Beanstalk uses EC2 underneath, why not just use EC2?

Answer:
With EC2, I have to manage the server and deployment configuration myself. Beanstalk handles much of that infrastructure management for me, so it's simpler when I want to deploy an application without managing everything manually.

CloudWatch

Q9. What is CloudWatch used for?

Answer:
CloudWatch is used for monitoring AWS resources and applications. For example, I can monitor EC2 CPU utilization, application logs, errors, and set alarms when certain metrics cross a threshold.

Q10. Your Node.js application is returning 500 errors in production. How can CloudWatch help?

Answer:
I can check the application logs in CloudWatch to find the error and stack trace. I can also check EC2 metrics such as CPU and memory-related monitoring to see whether there is a resource problem.
