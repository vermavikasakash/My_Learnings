SOL : 

Node.js child_process module creates separate OS processes. 

three ways to create new processes: exec(), fork(), and spawn()

exec() is used for small shell commands and buffers output in memory. 
spawn() is used for streaming large outputs efficiently. 
fork() is a specialized version for spawning Node.js processes with IPC communication support between parent and child processes.

1. exec()
Used to: execute shell commands
Behavior:
buffers entire output in memory
callback receives complete result

Good for: small output commands

Example: exec("ls", (err, stdout) => {})

Problem: not good for huge output because buffering can overflow memory
Real examples:
Git commands
Zip/unzip files
ImageMagick commands
FFmpeg commands
Deployment scripts

2. spawn()

Used to:
start long-running processes
stream large output data

Behavior:
returns streams (stdout, stderr)
does NOT buffer entire output

Good for:
large data
real-time streaming

Example:
const child = spawn("npm", ["run", "dev"]);

Real examples:
video processing
log streaming
ML model execution
large file operations
real-time stdout reading

3. fork()
Special version of spawn() for Node.js files.
Used for:
creating Node.js child workers
IPC (inter-process communication)

Key feature: Parent ↔ Child communication via message passing

Example:
child.send()
process.on("message")

Real examples:
background jobs
email workers
notification workers
queue consumers
CPU-heavy isolated tasks
