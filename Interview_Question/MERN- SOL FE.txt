What is hoisting?
During the creation phase, JavaScript processes declarations in their respective scope before executing the code.

Hoisting is JavaScript's behavior of moving declarations to the top of their scope during the creation phase. Variable declarations (var) are hoisted and initialized with undefined, while let and const are hoisted but remain in the Temporal Dead Zone until their declaration is executed. Function declarations are hoisted with their full implementation.

var → Hoisted, initialized as undefined.
let / const → Hoisted, but cannot be accessed before declaration (TDZ).
Function declarations → Fully hoisted.
Arrow functions → are not hoisted like function declarations.
Function expressions → Variable is hoisted, function assignment is not.

What is a closures ?
A closure is a function that remembers its variables and can access it from lexical (or outer) scope even tough the outer function has finished its execution.
JavaScript achieves this by preserving the function's lexical environment as long as the inner function still references it.

What is a Lexical Scope?
Lexical scope determines the scope of a variable is by where it is declared in the source code not when or where it is called

What is Garbage collector ?
A garbage collector is a built-in memory management component of the JavaScript engine that tracks allocated memory, determines which objects are no longer reachable, and reclaims that memory automatically.

What is event Delegation?
attach one listener on a parent and handle its child event via bubbling in one pass.
Event Delegation is a JavaScript technique where a single event listener is attached to a common parent element instead of multiple child elements. It works because of event bubbling. When a child element is clicked, the event bubbles up to the parent, and event.target identifies which child triggered the event. This reduces the number of event listeners, improves performance, and automatically supports dynamically added elements.

QUES 3.When to use rest parameter and spread parameter, also tell the difference

Rest parameters and spread parameters are both used to work with arrays and objects in JavaScript, but they serve different purposes.

Rest Parameters:
1. *Function arguments*: Rest parameters are used in function definitions to collect a variable number of arguments into an array.
2. *Syntax*: `...args`
3. *Example*: `function sum(...numbers) { return numbers.reduce((a, b) => a + b, 0); }`

Spread Parameters:
1. *Array and object literals*: Spread parameters are used in array and object literals to spread out the elements of an array or object.
2. *Syntax*: `...array` or `...object`
3. *Example*: `const arr1 = [1, 2, 3]; const arr2 = [...arr1, 4, 5];`

Key differences:
1. *Purpose*: Rest parameters collect arguments into an array, while spread parameters spread out the elements of an array or object.
2. *Usage*: Rest parameters are used in function definitions, while spread parameters are used in array and object literals.
3. *Direction*: Rest parameters gather elements, while spread parameters disperse elements.

 call() invokes the function immediately and accepts arguments individually (like list) after the this object.

Key differences:
1. *Argument passing*: `call` and `bind` passes arguments individually, while `apply` passes arguments as an array.
2. *Function invocation*: `call` and `apply` invoke the function immediately, while `bind` returns a new function without invoking it.

| --------------------------------- | -------- |
| invoke with custom this           | call     |
| invoke with array arguments       | apply    |
| preserve this for later execution | bind     |

apply(thisArg, [arg1, arg2, arg3])
 
note : first argument will be always object, if object is not present pass null.

React.memo is a higher-order component that memoizes a component and prevents unnecessary re-renders when its props haven't changed.
function App() {
    const [count, setCount] = useState(0);

    return (
        <>
            <button onClick={() => setCount(count + 1)}>
                Increment
            </button>

            <Child />
        </>
    );
}

function Child() {
    console.log("Child rendered");

    return <h1>Child</h1>;
}

App renders -> Child renders (Even though Child doesn't use count.)

fixes :--
const Child = React.memo(function Child() {
    console.log("Child rendered");

    return <h1>Child</h1>;
});

2. useMemo : useMemo memoizes the result of an expensive computation and recomputes it only when its dependencies change.

Suppose sorting 10,000 products.

const sortedProducts = products.sort(...);

This runs on every render.

fixes :--

const sortedProducts = useMemo(() => {
    return products.sort(...);
}, [products]);

Now React recalculates only when products changes.

3. useCallback : Memoizes a function so the same function reference is reused across renders until its dependencies change.

function App() {
    const [count, setCount] = useState(0);

    const handleClick = useCallback(() => {
        console.log("Clicked");
    }, []);

    return <Child onClick={handleClick} />;
}

const Child = React.memo(function Child({ onClick }) {
    console.log("Child Render");

    return <button onClick={onClick}>Click</button>;
});

| Type     | When it runs           | Use Case                        |
| -------- | ---------------------- | ------------------------------- |

import axios from 'axios';
// Create an axios instance
const api = axios.create({
  baseURL: 'https://example.com/api', // your base URL
});

axios.interceptors.request.use(
  (config) => {
    const token = localStorage.getItem('token');
    if (token) {
      config.headers.Authorization = `Bearer ${token}`;
    }
    return config; // must return config
  },
  (error) => Promise.reject(error)
);
 
Response Interceptor : This handles errors globally instead of in every .catch().

axios.interceptors.response.use(
  (response) => response,
  (error) => {
    if (error.response.status === 401) {

    }
    return Promise.reject(error);
  }
);

QUES 13.Virtualization in React
✅ ANS: Virtualization in React is a performance optimization technique where only the items visible on the screen are rendered, instead of rendering the entire list.

"Virtualization is a React performance optimization technique where only the items currently visible in the viewport are rendered instead of the entire list. As the user scrolls, off-screen items are unmounted and newly visible items are rendered. This significantly reduces the number of DOM nodes, lowers memory usage, improves initial render time, and provides smoother scrolling for large datasets. Popular libraries include react-window and @tanstack/react-virtual."

Imagine you have 100,000 products.

Without virtualization
If you do:
products.map((product) => (
  <ProductCard key={product.id} product={product} />
));

React creates 100,000 DOM elements.
Problems: Slow initial render, High memory usage, Laggy scrolling, Browser performance degrades

With virtualization : Suppose your screen can display only 10 items.

Instead of rendering all 100,000 items, React renders only: 1-10 items
When you scroll, React removes the items that go off-screen and renders the next visible ones:11-20 items

Although the list appears to contain all 100,000 items, at any moment there may only be around 10–20 DOM elements.

QUES 14.Throttling and debouncing in React
✅ ANS: Throttling and debouncing are techniques used in React (and general JavaScript) to control how frequently a function is executed, especially for performance optimization — like in scroll, resize, input, or button click events.

🔁 Debouncing
"Debouncing delays execution until the user stops triggering events for a specified duration. In React, this is commonly implemented using useEffect with setTimeout and cleanup via clearTimeout."

🧠 Real-world analogy:
Wait until a person stops typing before responding.

📦 Use case in React:
Search bar autocomplete
Form validations while typing

🔂 Throttling
limit how often a function can execute within a time interval.
allow execution only once every X ms

🧠 Real-world analogy:
You can press the elevator button rapidly, but it only responds once every few seconds.

📦 Use case in React:
Window resize listener
Scroll events
Preventing button spam

Summary Table :
| Feature  | Debounce                    | Throttle                             |
| -------- | --------------------------- | ------------------------------------ |
| Trigger  | After a delay of inactivity | At most once in a specified interval |
| Use case | Text input, search box      | Scroll, resize, rapid click          |
| Behavior | Delays execution            | Limits execution rate                |

throttle :

function throttle(fn, delay) {
    let lastExecuted = 0;

    return function () {
        const now = Date.now();

        if (now - lastExecuted >= delay) {
            fn();
            lastExecuted = now;
        }else{
            console.log("wait");
        }
    };
}

const throttledClick = throttle(clickButton, 3000);

throttledClick();throttledClick();throttledClick();

function clickButton() {
    console.log("clicked");
}

// debounce using js

function debounce(cb, delay) {
    let timer;

    return function () {

        clearTimeout(timer);

        timer = setTimeout(() => {
            cb();
        }, delay);

    };
}

const search = () => console.log("Searching...");

const debouncedSearch = debounce(search, 3000);

debouncedSearch();
debouncedSearch();
debouncedSearch();

QUES 17. What is currying in js or react
✅ ANS: Currying is a JavaScript technique that breaks a function into multiple smaller functions so we can pass arguments one at a time and reuse the function later.
Currying help us to create a new function by pre-filling some arguments of an existing function.


It allows partial application and improves function reusability.

js- example :

// Regular function
function add(a, b) {
  return a + b;
}

console.log(add(2, 3)); // Output: 5

// ✅ Curried version using closures
let curriedAdd = function(a) {
  return function(b) {
    console.log(a + b);    // Output: 5
  };
}

curriedAdd(2)(3); 

 Explanation:
curriedAdd(2) returns a function.

Then (3) calls that returned function.

Final result is 2 + 3 = 5.

// ✅ Curried version using bind method

let curriedAdd = function(a,b) {
    console.log(a + b);

let curriedAddTwo = curriedAdd.bind(this,2);
curriedAddTwo(3);

Ques 18. Difference between oauth and jwt
✅ ANS: OAuth is an authorization framework that allows users to log in using third-party providers like Google or GitHub. JWT is a token format used to securely store user information after authentication. A common flow is: user logs in with Google using OAuth, then our backend generates a JWT for future authenticated requests.

| OAuth                                       | JWT                                                |
| ------------------------------------------- | -------------------------------------------------- |
| Authorization framework                     | Token format                                       |
| Used for third-party login (Google, GitHub) | Used to identify/authenticate users                |
| Grants permission to access resources       | Stores user information securely in a signed token |

Ques 19. Difference between server and serverless
✅ ANS: In a traditional server architecture, we manage the server, deployment, and scaling ourselves. In serverless architecture, cloud providers like AWS Lambda manage the infrastructure, automatically scale the application, and we pay only for the execution time of our functions.

| Server                | Serverless                                |
| --------------------- | ----------------------------------------- |
| You manage the server | Cloud provider manages the infrastructure |
| Always running        | Runs only when triggered                  |
| Manual scaling        | Automatic scaling                         |
| Pay for server uptime | Pay only for execution time               |

QUES 20.What is React query (TanStack Query) & useMutation?
✅ ANS: React Query (now called TanStack Query) is a library that helps you fetch, cache, synchronize, and update server data in React applications.

"React Query, now known as TanStack Query, is a library for managing server state in React applications. It simplifies data fetching by handling caching, loading and error states, background refetching, and request deduplication. Instead of writing useEffect and useState for every API call, we use useQuery to fetch data and useMutation for create, update, or delete operations. It also caches responses using query keys and can automatically refetch stale data, making applications faster and reducing unnecessary network requests."


React's useState is for client state, while React Query is for server state.
In useState and useEffect we have to manage: Loading state, Error state, API call, Caching, Refetching, Duplicate requests
That's a lot of boilerplate.

with recat query:

import { useQuery } from "@tanstack/react-query";

 const { data, isLoading, error } = useQuery({
    queryKey: ["users"],
    queryFn: () => fetch("/api/users").then(res => res.json())
  });

Fetching data uses useQuery. Changing data uses useMutation.

const mutation = useMutation({

    fetch("/api/users", {

    })

QUES 21.What is Microfrontend Architecture & the advantages of Microfrontends?
✅ ANS: Microfrontend Architecture is a frontend design approach where a large application is divided into smaller, independently developed and deployed frontend modules, similar to how microservices split a backend. 
Each module, such as Login, Cart, or Product, can be owned by a separate team and deployed independently.
A Host or Shell application composes these modules into a single user experience. This architecture improves team autonomy, scalability, and deployment speed, but introduces challenges like shared state management, consistent UI, and communication between microfrontends. Common implementation techniques include Webpack Module Federation and Single-SPA

" Host or Shell application composes all the microfrontends at runtime. The browser first loads the Host application, which then dynamically fetches the individual microfrontends from their deployment URLs. These are rendered together as a single application, so the user experiences one seamless website."
