QUE 1 : Difference between rem,em,px

Ans :In CSS, `rem`, `em`, and `px` are units of measurement used to define the size of elements, such as text, margins, and padding.

PX (Pixels):
1. *Absolute unit*: `px` is an absolute unit, meaning it's fixed and doesn't change based on other factors.
2. *Screen-based*: `px` is based on the screen's resolution, making it suitable for digital displays.
3. *Not scalable*: `px` values don't scale when the user zooms in or out of the page.

EM:
1. *Relative unit*: `em` is a relative unit, meaning it's based on the font size of the parent element.
2. *Scalable*: `em` values scale when the user zooms in or out of the page.
3. *Cascading*: `em` values can be affected by the font size of parent elements, making it useful for creating scalable typography.

REM (Root EM):
1. *Relative unit*: `rem` is a relative unit, meaning it's based on the root element's font size (usually the `html` element).
2. *Scalable*: `rem` values scale when the user zooms in or out of the page.
3. *Not cascading*: `rem` values are not affected by the font size of parent elements, making it useful for creating consistent typography.

Key differences:
1. *Scalability*: `em` and `rem` are scalable, while `px` is not.
2. *Relative vs. absolute*: `em` and `rem` are relative units, while `px` is an absolute unit.
3. *Cascading behavior*: `em` values can be affected by parent elements, while `rem` values are not.

When to use each:
1. *Use `px` for*: Fixed-size elements, such as borders, margins, or padding.
2. *Use `em` for*: Scalable typography, especially when you want the font size to be relative to the parent element.
3. *Use `rem` for*: Consistent typography, especially when you want the font size to be relative to the root element.

What is hoisting?
js hoist declarations to the top of their scope.
Hoisting is JavaScript's behavior of moving declarations to the top of their scope during the creation phase. Variable declarations (var) are hoisted and initialized with undefined, while let and const are hoisted but remain in the Temporal Dead Zone until their declaration is executed. Function declarations are hoisted with their full implementation.

var → Hoisted, initialized as undefined.
let / const → Hoisted, but cannot be accessed before declaration (TDZ).
Function declarations → Fully hoisted.
Function expressions → Variable is hoisted, function assignment is not.

What is a closures ?
A closure is a function that remembers and can access variables from its lexical (outer) scope even after the outer function has finished executing. JavaScript achieves this by preserving the function's lexical environment as long as the inner function still references it.

What is a Lexical Scope?
Lexical scope means a function's scope is determined by where it is defined in the source code, not where it is called.

What is Garbage collector ?
A garbage collector is a built-in memory management component of the JavaScript engine that tracks allocated memory, determines which objects are no longer reachable, and reclaims that memory automatically.

What is event Delegation?
Event Delegation is a JavaScript technique where a single event listener is attached to a common parent element instead of multiple child elements. It works because of event bubbling. When a child element is clicked, the event bubbles up to the parent, and event.target identifies which child triggered the event. This reduces the number of event listeners, improves performance, and automatically supports dynamically added elements.

Rest Parameters:
1. *Function arguments*: Rest parameters are used in function definitions to collect a variable number of arguments into an array.
2. *Syntax*: `...args`

1. *Array and object literals*: Spread parameters are used in array and object literals to spread out the elements of an array or object.

3. *Direction*: Rest parameters gather elements, while spread parameters disperse elements.

Summary Table :
| Feature  | Debounce                    | Throttle                             |
| -------- | --------------------------- | ------------------------------------ |

| Use case | Text input, search box      | Scroll, resize, rapid click          |
| Behavior | Delays execution            | Limits execution rate                |

throttle :

function throttle(fn, delay) {
    let lastExecuted = 0;

    return function () {
        const now = Date.now();

        if (now - lastExecuted >= delay) {
            fn();
            lastExecuted = now;
        }else{
            console.log("wait");
        }
    };
}

const throttledClick = throttle(clickButton, 3000);

QUES 18. What is currying in js or react
✅ ANS: Currying is a technique in which a function returns another function to handle one argument at a time, and allowing arguments to be passed separately rather than all at once.

Currying is a technique in JavaScript where a function doesn't take all arguments at once, but instead takes them one by one — each returning a new function that takes the next argument.

"Currying converts a function with multiple arguments into a sequence of functions that each take one argument. We use it to create reusable, specialized functions by fixing some arguments in advance. It's commonly used in React event handlers, Express middleware (like authorize('ADMIN')), logging utilities, validators, and API wrappers. Currying also improves function composition and reduces repeated arguments."

js- example :

// Regular function
function add(a, b) {
  return a + b;
}

console.log(add(2, 3)); // Output: 5

// ✅ Curried version using closures
let curriedAdd = function(a) {
  return function(b) {
    console.log(a + b);    // Output: 5
  };
}

curriedAdd(2)(3); 

 Explanation:
curriedAdd(2) returns a function.

Then (3) calls that returned function.

Final result is 2 + 3 = 5.

// ✅ Curried version using bind method

let curriedAdd = function(a,b) {
    console.log(a + b);
}
let curriedAddTwo = curriedAdd.bind(this,2);
curriedAddTwo(3);

Ques 19. Difference between oauth and jwt
✅ ANS: OAuth is an authorization framework that allows users to log in using third-party providers like Google or GitHub. JWT is a token format used to securely store user information after authentication. A common flow is: user logs in with Google using OAuth, then our backend generates a JWT for future authenticated requests.

| OAuth                                       | JWT                                                |
| ------------------------------------------- | -------------------------------------------------- |
| Authorization framework                     | Token format                                       |
| Used for third-party login (Google, GitHub) | Used to identify/authenticate users                |
| Grants permission to access resources       | Stores user information securely in a signed token |

Ques 20. Difference between server and serverless
✅ ANS: In a traditional server architecture, we manage the server, deployment, and scaling ourselves. In serverless architecture, cloud providers like AWS Lambda manage the infrastructure, automatically scale the application, and we pay only for the execution time of our functions.

| Server                | Serverless                                |
| --------------------- | ----------------------------------------- |
| You manage the server | Cloud provider manages the infrastructure |
| Always running        | Runs only when triggered                  |
| Manual scaling        | Automatic scaling                         |
| Pay for server uptime | Pay only for execution time               |
